# UK 企业数据体检样例

将 [uk-company-profile-demo.csv](uk-company-profile-demo.csv) 上传到侧栏「数据准备」。
本文件带 UTF-8 BOM，便于常见表格软件打开。可同时添加
[uk-company-relations-demo.json](uk-company-relations-demo.json)，保存为一个联合分析案例。

样本来自 `datasets/uk_dataset_v1/train.json` 的企业节点。按企业 ID 的 SHA-256
排序，选取 96 条标签 0 和 4 条标签 1；只用于展示数据体检，不能代表完整 UK 数据分布，
也不包含图的原始边或超边。`adverse_status` 是登记状态快照：
1 表示企业正处于困境程序，0 表示 Active，不能解释为未来违约标签或违约概率。

为了测试脏数据检测，样例在抽样后作了三处**演示性改动**：

- 第一行的 `n_charges` 清空。
- 第二行的 `max_span` 写为「未知」。
- 复制第三行作为最后一行。

因此上传后应看到 101 行、1 行完全重复，`n_charges` 和 `max_span` 各缺失 1 个值。
源数据中还有 4 行 `community` 为「未知」，当前体检规则也会将它计为缺失。
原始 UK 数据和模型训练集均未修改。智能体建议只供确认；此样例不能直接训练 RiskGNN+。

## 联合分析与导入

配套 JSON 是原始 train.json 在上述100家企业上的诱导子图：仅保留两端均在样本中的边，
群组取样本企业交集且至少保留2家。不用统计数量反推关系，也不补造节点。
节点只保留ID，避免把样例刻意制造的缺失与原始数值误当作已确认清洗规则。
每条关系携带原快照数组位置，导入时另记录上传文件摘要与本文件数组位置。

可以一次选择CSV和JSON，或打开旧CSV案例补充JSON。后者创建新版本，需重新确认
缺失值和去重规则并试运行；试运行通过后在卡片确认导入。图JSON中的额外企业属性
只核验冲突，不自动覆盖或补入CSV属性；属性以已确认的CSV规则为准。

完整英国图仍建议用模型工作台ZIP适配器；案例主表保持2 MiB/50000行、转换产物16 MiB限制。

本配套子图实际为100个节点、0条普通边、17个群组；普通边为空是抽样后的真实结果。
