# 数据集清空

建模工作台的数据集详情提供“清空数据集”。用户输入完整数据集名称后确认，
后端 `POST /modeling/clear-dataset` 再次检查账号归属、显式确认及名称匹配。

## 范围

一次事务移除选中数据集的企业记录（含关系/超边/事件）、导入状态、预测、
已发布模型、实验（含重试链）、对应提交/取消投递记录和数据集业务入口。
其他数据集与历史来源记录不受影响。
对象存储的上传包、派生文件、模型制品及独立模型服务的作业记录保留，
本操作不是存储空间回收或制品擦除。重新上传会生成新的数据集 ID。

数据集业务入口移除后，后台企业同步器不会自动恢复已清空的数据。
工作台清除当前选择并刷新列表；总览/检索中的已失效本地默认选择回落到可用数据源。
显式指向旧 ID 的链接返回资源不存在。

## 并发与错误

清空依次锁定数据集、实验和模型版本；新实验在写入前取得同一数据集锁，
企业导入与清空共享数据集锁，模型发布/删除共享实验锁，预测持有模型版本锁。
单事务按外键依赖顺序清理，重试链在单条删除语句中移除。

- `MODELING_RESOURCE_NOT_FOUND`：资源不存在或不属于当前账号。
- `MODELING_CONFIRMATION_MISMATCH`：确认名称与当前数据集名称不一致。
- `MODELING_DATASET_BUSY`：已提交数据集的校验或任一关联实验尚未终止。
  等待校验完成，或取消实验并等待取消完成后再清空。

测试使用独立 PostgreSQL schema，覆盖账号隔离、名称/确认校验、运行中保护、
关联数据清理、其他数据集保留、目录移除及重新上传导入。
