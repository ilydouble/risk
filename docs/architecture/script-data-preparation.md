# 脚本驱动的数据准备

## 用户流程

`/data-prep` 是独立任务工作区：上传原始文件、选择目标适配器、描述转换要求，
在同一页面与智能体协作编辑Python，执行、读取日志、修复并下载或交付标准ZIP。
原始数据不要求先转换成企业主表或图JSON，也不需要先确认字段映射。

1. 创建任务，填写独立数据集标识、版本、目标适配器和转换要求。
2. 添加最多16个原始文件，合计64 MiB；支持目录相对路径，拒绝重名和目录冲突。
3. 智能体读取有界文件预览、目标结构和历史真实日志，提出完整Python脚本。
4. “生成并试运行”保存脚本并排队；也可手动编辑后“保存并运行校验”。
5. 后台执行器运行冻结脚本，打包并调用模型适配器全量校验。
6. 失败时查看日志、继续讨论和修复；成功后下载同一数据包或直接交付工作台。
7. 工作台再次独立校验，通过后才能创建实验。

当前目标来自已部署的ACRA、SMEsD与UK适配器。它们各有特征与语义约束，
不能把任意企业表仅改名后声明为某个公开数据集。数据集身份由任务填写，
适配器身份由预设确定，两者独立；用户可在目标要求中查看必需文件和说明。

## 脚本契约

Python3.12环境提供pandas、numpy、pyarrow、duckdb和标准库；不在运行中安装依赖。
使用 `os.environ['INPUT_DIR']` 读取任务文件；使用 `os.environ['OUTPUT_DIR']` 写出目标文件。
系统负责生成 `risk_dataset_contract.json`、保留 `_preparation/convert.py` 和执行来源说明。
脚本不能使用保留目录 `_preparation`；生成的旧根契约由系统替换。

执行脚本限65秒、CPU时间60秒、容器内存2 GiB、128进程，单输出文件64 MiB，
总输出128 MiB，ZIP最多64 MiB。日志只返回末16000字符，模型校验日志最多12000字符。
这是当前有界转换版本；更大数据须扩大受控执行资源与产物存储，不通过拆分企业伪造独立划分。

数据库迁移SQL可作为脚本产物生成，但当前执行器不连接外部数据库。
若需要直接读源库或写目标库，应新增专用、受限的数据连接能力，不能向脚本注入业务服务密钥。
标签定义、关系依据、划分、补值和编码需要明确业务依据；智能体不确定时先询问。

## 持久化与一致性

V0013新增 `script_preparations` 与 `script_preparation_runs`。
任务原始字节和摘要固定；替换输入通过新建任务实现。
产物版本为任务版本前缀加 `-r<revision>`，避免脚本变更后复用同一数据版本。
脚本与要求使用revision乐观锁，防止模型长响应覆盖用户的新修改。
每次运行冻结源摘要、代码、代码摘要、要求、目标、数据版本和运行镜像ID。
草稿可继续编辑；历史运行的脚本、日志及产物保持不变，可在历史中选择和交付。
当前保留最近20次运行的界面入口，数据库不自动删除历史产物。

Worker通过 `FOR UPDATE SKIP LOCKED` 领取排队任务；同一任务只允许一个排队或执行中的运行。
服务中断超过5分钟的运行标为失败，用户可以重跑。执行结果只有完整数据包摘要核对通过才保存。
输入、对话、日志、历史和下载均按登录账号隔离，不信任客户端替换账号。

交付复用工作台对象存储与完成上传链路。运行记录与上传数据集ID原子保存，
失败重试重新上传同一对象、重复成功返回同一数据集，工作台只排一次校验。
工作台来源快照记录任务、运行、脚本/输入/产物摘要和镜像；ZIP内另含独立来源清单。
原始文件与产物暂存PostgreSQL字节列，是当前大小限制下的实现取舍。

## 执行隔离

可信的 `preparation-runner` 是唯一拥有Docker socket的服务，仅在Compose内部提供带token的固定接口。
业务后端、worker和智能体都不能传入镜像、挂载、网络或Docker命令参数。
每个运行启动独立容器，不挂宿主目录或业务卷，网络为none，根文件系统只读，
输入为root拥有的只读文件；生成代码降为UID/GID65534，输出与临时目录位于受限tmpfs。
运行镜像只复制依赖和必要适配器代码，不复制研究产物或用户工作空间。
脚本环境没有LLM、数据库、存储凭证，也无法访问Docker socket。

可信启动器只保留切换UID/GID和清理子进程的能力，生成代码降权后没有这些能力。
超时或异常后调度器按随机容器名清理，不执行宿主Python作为后备方案。
这适用于当前可信账号内部工具；Docker容器共享内核，面对公开不可信多租户应改用更强的隔离执行基础设施。

## 部署

先确保 `risk-riskgnn:local` 已按现有模型服务流程构建。随后执行：

```bash
docker compose build preparation-runtime preparation-runner backend preparation-worker gateway
docker compose up -d backend preparation-runner preparation-worker gateway
```

`preparation-runtime` 是构建运行镜像的一次性服务；runner启动前它执行true并退出。
runtime以现有验证过的linux/amd64模型依赖为基线；不启动模型训练。
后端启动时自动迁移到V0013。生产使用独立的 `PREPARATION_RUNNER_TOKEN`。
本机开发可以单独启动 `backend/script_runner/server.py`（需要Docker CLI与runtime镜像），
配置后端 `PREPARATION_RUNNER_URL` 后另启动 `python -m risk_api.modules.data_prep.script_worker`。
服务没有向宿主机发布runner端口；前端仍通过业务后端调用。

## 兼容与验证

旧案例、字段映射、浏览数据导入保留在 `/data-prep/legacy`；旧preparation查询参数自动转到历史页。
通用助手的旧案例入口保持兼容，新任务的对话和脚本操作全部在任务工作区进行。
旧手动目录打包保留兼容入口，主流程只交付执行器实际生成的产物。

测试覆盖账号隔离、乐观锁、冻结执行、排队幂等、交付重试、输入路径与脚本语法。
真实Docker测试覆盖CSV转换、完整模型校验、前导零、输入/根目录只读、无网络及失败无产物。
Strands MockTransport测试验证真实工具协议、输入/契约/日志读取与仅提出草稿。
