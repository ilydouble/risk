# 数据准备与模型适配

## 概念与流程

数据准备记录包含一份有固定摘要的原始CSV、统计画像、分析报告和字段映射方案。
映射方案描述源字段用途、目标结构、转换方式及依据；确认方案不表示已经执行转换。
训练数据包是符合已部署模型适配器契约的派生产物，与原始案例不是同一对象。

```text
保存原始CSV → 数据体检 → 智能分析提出字段用途/目标/方法
                          ↓
                  编辑、核对并确认映射
                          ↓
                  移交工作台，共用原记录
                          ↓
          按实际适配器补齐关系数据、标签语义和独立划分
                          ↓
             导入派生契约ZIP，封存来源与确认映射
                          ↓
               模型侧校验通过后才允许训练
```

## 为什么不能直接把任意CSV变成训练包

当前工作台的“映射”由模型侧数据适配器解释，不是通用列名重命名。
例如UK适配器需要三个独立快照、审计与元数据，且包含特定的七维特征、四类关系和三类超边。
单表中的企业编号、0/1或同组属性，不能证明标签业务含义、跨表关系或独立测试划分。
数据准备给出建议，用户确认语义；实际模型适配器负责可执行规则和训练输入校验。

本次没有增加任意CSV自动构图或自动划分。工作台清楚显示“映射已确认，待模型适配”，保留已有标准ZIP的直接导入入口。
原文件与映射交付包仅含 `source.csv`、准备记录及说明，没有模型训练契约，不能冒充可训练输入。

## 保存、复用和隔离

- V0010新增按账号的准备记录；CSV上限仍为2 MiB/50000行，源字节保存在业务数据库。
- 同账号相同SHA复用准备记录，不同账号独立；源文件不原地覆盖。
- 报告生成使用已保存统计，不信任客户端替换的画像；报告成功后沿用同一准备ID保存。
- 新报告只能填充未编辑的初始映射，不能覆盖用户编辑/确认的方案。
- 确认必须覆盖全部源字段，解决待确认项，指定一个企业标识、至少一个特征，目标不得冲突。
- 修改已确认的方案后需重新确认；移交记录仍在工作台展示“待确认”。
- 工作台导入派生ZIP时校验来源归属和确认状态，保存源摘要及映射快照。
- 来源ID为逻辑引用，目前准备记录没有删除入口；快照保证后续编辑不会改变包的来源解释。

## 页面衔接

数据准备可恢复已保存案例、生成报告、编辑/保存映射、确认并转入工作台。
工作台通过准备ID继续使用源记录，允许继续编辑，并可返回原案例查看统计与报告。
原始CSV只需保存一次；派生训练包是经过适配的新产物，不能视为重复上传同一原文件。


## 带案例进入助手

- 体检完成后通过“让助手确认映射”进入 `/chat?preparation=<id>`，不重复上传。
- 助手按账号读取准备记录；加载中或读取失败时禁止提交案例问题。
- 顶部固定案例卡片显示文件、行数、字段数、确认状态和报告状态。
- 点击“让助手梳理待确认问题”提交首轮问题；后续问题附带同一准备ID，工具读取最新已保存方案。
- 上下文附在保存的用户消息中，聊天界面显示关联标记；没有新增 HTTP DTO。
- 映射面板复用原保存接口；对话建议不会自动修改映射，需用户核对并保存。
- 新建对话的内部导航保留案例参数，刷新恢复案例与对话；切换历史对话或手动新建会解除案例参数。
- 返回数据准备时携带对话ID，再进入助手可继续原对话。
- 尚未接入转换脚本执行和正式导入，不展示无法执行的试运行/导入按钮。
