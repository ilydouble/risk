# 建模领域模型与决策

## 通用语言

| 术语 | 固定含义 |
| --- | --- |
| 标准数据包 | 外部适配器生成、通过 Bundle v1 校验的 ZIP；不是客户原始业务库导出物 |
| 样本 | `samples` 中的一行，是模型损失和评估的最小单位 |
| 贷款申请样本 | 一次申请及其观察时点信息，目标可定义固定窗口逾期或违约 |
| 企业快照样本 | 一个企业在一个观察时点的状态，目标是经营异常等企业级事件 |
| 图快照 | 样本观察时点可见的节点、关系、事件和超边集合 |
| 数据集 | 已上传数据包及其清单、能力、校验状态和聚合画像 |
| 实验 | 对一个 ready 数据集运行的一组确定配置与模型变体 |
| 变体 | 模型阶梯中的一个可比较实现，例如 HGB 或 `gnn_no_hyper` |
| 模型制品 | 实验产生的预处理、特征选择、模型参数、结果与哈希清单；默认不发布 |

## 不变量

- `samples` 是唯一训练样本入口；工作台不连接或关联银行原始业务表。
- 标签、预测窗口和正类由 metadata 固定，训练页面不能重新解释其业务含义。
- 所有预处理和特征选择只拟合 train；validation 用于早停/选择，test 只报告。
- 图中的事件不得晚于对应快照；引用不完整时整包失败，不静默丢弃。
- 企业快照实验只能称为企业经营风险，不得展示为贷款违约概率。
- 公开基准、演示评分、用户实验制品拥有不同身份和生命周期，不能互相覆盖。

## 架构决策：字段映射位于系统之外

决定：客户原始数据到 Bundle v1 的映射、业务表关联、标签生成和图快照生成由外部适配脚本完成。

理由：现场数据结构未知，把不稳定的客户语义隔离在适配层后，工作台内部只维护一个可测试的训练
契约；同一训练引擎即可覆盖贷款申请和企业快照两类任务。代价是每个新数据源必须先编写并审计
适配脚本，工作台不会替错误标签或时间穿越兜底。

## 架构决策：训练是本地异步能力

决定：FastAPI只登记任务，本地模型 Worker 从 PostgreSQL领取并从 RustFS读取数据；Compose 不运行
模型容器。理由是训练依赖、内存占用和运行时长不应进入 HTTP 生命周期，同时满足断网比赛环境。
Neo4j仍服务产品演示图谱，训练图完全来自数据包，避免线上图状态污染实验复现。
