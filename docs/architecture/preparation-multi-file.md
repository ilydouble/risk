# 多文件数据准备案例

## 范围与关联

一个案例包含一张UTF-8企业属性CSV和最多7个图JSON。CSV沿用2 MiB、50000行、
100列限制；图JSON每个最多64 MiB、500000条节点/边/群组记录，总源文件不超过96 MiB。
本入口用于可核验的小规模业务导入，转换产物最多16 MiB；完整英国包仍使用工作台ZIP适配器。

图JSON结构沿用英国快照：可选nodes/feature_names，edges含source/target/relation/weight，
hyperedges含kind/members。企业ID须是字符串，保留前导零。人物和非空events暂不支持，
未知格式明确拒绝，不执行文件里的代码。图节点属性仅核验冲突，CSV确认规则决定导入属性。

同案例代表联合分析范围，不代表文件可直接合并。CSV规则中的enterprise.id确定关联键；
试运行用转换后的企业集合核验全部图节点、关系端点、群组成员，缺失对象阻止整批导入。
图节点的共同属性与CSV转换值冲突、重复边证据不一致也阻断；不自动填造节点或覆盖属性。
完全相同的关系只保留一条，报告单独列出去重数，不与CSV行去重混合。

## 持久化与版本

POST /api/v1/data-prep/inspect-case接收files，选填preparationId表示补充文件。
新案例的CSV和图文件以确定性、按文件名排序的内部容器保存于Preparation.source，
原文件字节不变；案例SHA覆盖整个容器，每个文件另存摘要、角色和图规模。
单CSV继续使用既有字节与SHA，不改历史案例和任务版本。

补充文件先按账号读取旧案例，再生成不可变新案例版本，返回previousPreparationId。
不覆盖旧报告、规则、对话或已导入数据；主表不变时继承字段规则草稿，重置确认状态，
不继承旧报告或任务结果。新版本需重新分析、核对规则、试运行和确认导入。
相同账号、相同文件集合重复保存复用同一案例。文件名重复或多张CSV明确拒绝，
避免不经确认地替换来源或猜测哪张是主表。

## 执行与追溯

enterprise-case-v1与旧enterprise-csv-v1分开封存版本。任务指纹覆盖案例SHA、映射和规则。
试运行同时输出企业/边/群组数量、按文件覆盖率、缺失ID示例、冲突和重复关系数量。
错误定位JSON文件及数组位置；失败结果不可部分导入。

正式导入仍须页面明确确认，助手只有保存规则/试运行/查结果工具。企业和关系在同一
数据库事务写入workbench_enterprise_records，重复提交同任务返回同一数据集。
CSV企业保留逐字段及物理行追溯；图记录的sourceRecord保存文件名、文件SHA和数组位置。
全部读取、补充、试运行和导入按账号隔离，关系仅引用本案例导入企业。

导入后概览显示各类型数量，企业详情提供本数据集局部关系图谱、关联记录和来源证据。
群组以独立节点及无向成员线展示，画布限制和范围见[企业关系图谱](enterprise-relation-graph.md)。
不自动写入Neo4j；此转换产物仍为browseOnly，不声明训练就绪或生成模型预测。

## 验证

回归覆盖文件顺序幂等、字节保真、前导零、非法图结构、属性冲突、悬空引用、重复关系、
不可变补充版本、账号隔离、整批阻断、导入幂等及旧CSV来源追溯。
