## 披露时间和版本

1. 本期继续固定使用 v3 选定的基线财报，财务值完全一致。质量隔离、币种、字段缺失、国家等旧列均不改变。
2. 比较期只能使用其来源财报的可用时间，不能把比较期末视作该数值已公开。沿用“申报月份次月末”的保守可用日，精确申报日期保持空白和未验证标志。
3. 历史期间优先使用同一基线财报的比较披露。缺少时可用其他本地财报，但其可用日不晚于基线财报的保守可用日、财报期末不晚于基线期末。
4. 同一公司、同一期间先固定整份来源版本，再计算各指标；不为某个指标选择更完整的另一版本。其他来源按较新的可用日、财报期末和报告 ID 确定顺序。
5. 继承 v3 的实体识别、受信命名空间、Original 维度、期限映射、事实冲突和字段质量规则，继续排除合并/分部/修订维度的混用。以基线财报自身期末为上界提取比较数据。

较早财报中的可比数可能经重述；这里使用当时选定披露版本提供的数值，不宣称它就是更早时点最初公开的数值。来源版本和可用日均可追溯。

## 特征规则

对原有 17 项指标增加上期值、绝对差值、相对变化、三期年化斜率及各自 missing 标志。逐指标保存前期日期/单位、趋势状态和斜率所用日期；这些日期和状态属于审计列。

- 相邻比较期末相距 330—400 天才作为近似年度比较。
- 收入、利润和平均员工等期间指标，两期各自持续 330—400 天、长度相差不超过 31 天且不重叠，才生成年度差值。短期首份报表不直接与完整年度相减并称为年度变化。
- 金额变化要求同单位/币种，不进行未经历史汇率支持的换算。
- 同一指标从已选定的历史版本中选择最近的满足比较条件的前期；如果没有可比前期，仍可保留最近披露的前期值，但差值和增长率缺失。不同指标可能使用不同前期，实际日期单列。
- 差值为本期减前期；负净资产或亏损仍可以计算差值。仅前期大于零时计算 `(本期－前期)/前期`，0.25 表示 25%；零或负基数的相对变化留空。
- 三期均满足相邻年度比较条件时，按真实期末间隔做三点最小二乘斜率，按 365.25 天折算金额/年或人数/年，不把不规则间隔当作等距年度。
- 增加流动比率与现金比率，以及相应前期值和年度差值；同一期分子/分母必须同币种，流动负债必须为正。分子为零可以得到合法的零比率。

主要可比差值覆盖：权益 157,872、净流动资产 152,019、流动资产 148,020、流动负债 145,879、现金 82,914、营业收入 3,314、税后损益 5,082 条观察。完整逐指标覆盖在 `trend-coverage.csv`。

以上可比性按日期、币种和期间检查，不替代逐份会计政策、科目重分类或源标注真实性复核。v3 已保留的质量警告继续可追溯。

## 交付与验证

训练候选表 `features.csv` 包含 v3 全部原列及新增列，可按相同企业 ID/样本 ID 与原图关联；`labels.csv` 与 v3 原字节相同。`feature-contract.json` 明确数值、missing 和单位类别候选，审计 ID、日期和状态不自动编码入模型。

`financial-history.csv` 保存来源财报和期间版本；`financial-report-sources.csv` 保存来源及申报日期未核实标记；`sample-history-links.csv` 保存每条观察实际选择的历史行。`history-facts.jsonl.gz`、`history-source-facts.jsonl.gz` 与 `history-quality-issues.jsonl.gz` 保存清洗事实、质量处理前事实和复核原因。

额外 2,364 份原件 gzip 副本随扩展包提供，位于 `sources/additional-filings/<报告ID前两位>/`。v3 基线原件沿用既有缓存和原源数据包，未重复打包。原 v3 图数据包仍为图结构来源；本扩展不代替它。

独立验证逐份关联来源元数据，逐事实对照长表，检查隔离字段、披露时间、全体原观察列/标签不变，并重新计算绝对变化、相对变化、三期斜率和比率；未训练模型，不声称新增特征提高预测准确率。
