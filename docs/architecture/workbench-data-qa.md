# 问答中的工作台问数

## 使用

登录后从侧栏问答入口进入 `/chat`，用自然语言提问。
可在问题中说明数据集和模型范围，由助手查询目录并补全调用条件。
独立“工作台问数”菜单和页面已移除，旧地址 `/data-qa` 替换跳转到 `/chat`。
例如：

- 我有哪些数据集？列出名称和校验状态。
- 各数据集分别导入了多少家企业？
- 训练实验按执行状态分别有多少个？
- 列出风险概率最高的前10条预测，包含模型名称和企业ID。
- 各模型已保存预测中，高风险和低风险分别有多少条？
- 普通关系、超边和事件分别有多少条？

助手调用 `workbench_catalog` / `workbench_ask`，底层问数服务与 HTTP 接口继续保留。
助手沿用当前登录账号和本轮模型配置，工具卡片展示结果、SQL、计划及警告。
每次工具问数独立执行，追问由助手补全查询条件。

## 参考与实现取舍

参考本地 `kgraph-studio` 的 metadata_qa 流程：提供表结构与语义、
限定范围、执行查询、返回真实结果及可检查的SQL和过程。

本项目使用固定工作台语义视图；模型返回结构化查询计划，后端生成SQL。
未引入KGraph的本体、Schema图增强或四模式对照实验。
模型只负责理解问题，结果摘要由数据库返回值生成，不采信模型自报数字。

## 数据范围

| 语义视图 | 物理表 | 口径 |
| --- | --- | --- |
| datasets | workbench_datasets | 数据集与校验状态 |
| runs | workbench_runs | 训练实验、算法标识与状态 |
| models | workbench_model_versions | 已登记模型，关联实验和数据集 |
| imports | workbench_enterprise_imports | 企业数据导入摘要 |
| records | workbench_enterprise_records | company/person/edge/hyperedge/event全部记录 |
| enterprises | workbench_enterprise_records | 仅company记录 |
| predictions | workbench_enterprise_predictions | 已保存的模型/企业预测，关联模型、数据集与可用企业名 |

内部任务派发表、账号表、密钥、对象存储路径不向问数开放。
所有查询在聚合前限定当前账号；数据集和模型选择在后端独立校验权限。
模型选择只影响predictions查询；数据集选择影响所有视图。
名称可以重复，助手应通过目录确认ID；对比模型时保留模型ID。

未指定数据集时企业计数为各数据集企业记录总数，不能声称是跨数据集去重工商主体。
预测表每行是一对模型/企业；未指定模型时，同一企业可能出现多条预测。
只读取已保存预测，不触发推理、不自动导入数据、不生成授信决定。
高风险默认使用predicted_label=1；用户明确提供概率阈值时按probability筛选。
主分类概率未校准，不等同于贷款违约概率。

## 查询与执行约束

- `POST /api/v1/data-qa/catalog`：获取语义字段及账号可选数据集/模型。
- `POST /api/v1/data-qa/ask`：问题、可选datasetId和modelId，使用既有会话认证及四字段信封。
- 支持明细字段、AND筛选、至多3个分组字段、计数/去重计数/数值聚合、排序。
- 固定字段白名单，SQLAlchemy绑定所有筛选参数；模型不能提交或执行SQL。
- 一次选择一个语义视图，固定连接由后端维护，不开放任意多表连接或JSON内部属性统计。
- 数据库事务强制READ ONLY，单条SQL超时3秒，整个数据库操作超时5秒。
- 大模型规划总预算50秒，校验失败最多修正一次；空结果不会触发重试或放宽条件。
- 问题最多2000字符；最多返回100行，额外读取1行判断是否截断，聚合在截断前计算。
- 单元格长文本/JSON超过4000字符会标记展示截断，筛选和统计仍使用完整数据。
- 范围选择器最多显示最近200个数据集及模型；全部范围查询不受选择器条数限制。
- SQL展示参数占位符，计划展示业务筛选条件；账号身份参数不返回前端。

## 验证与限制

使用独立临时PostgreSQL创建真实工作台表，验证所有视图、账号隔离、
模型和企业连接、概率筛选、跨账号范围拒绝及只读事务拒绝写入。
并验证非法查询计划、绑定参数、空结果保留条件、修正预算和接口认证。

数据库集成测试可指定 `RISK_TEST_DATABASE_URL`；测试创建独立schema并自动清理。
新增问数、既有问答、API契约与企业数据测试共53项通过；前端lint、类型检查和构建通过。
当前开发环境无法连接现场内网大模型，尚未完成真实Qwen端到端问数验收。
实际验收应使用示例问题核对SQL/计划与表中真实计数，不能只检查页面是否给出文字。
