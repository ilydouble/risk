这两个问题实际上应该统一处理：不要直接从用户数据“生成一张确定图”，而应先构建带来源、时间和置信度的关系证据图，再由模型生成用于训练的图视图。

```
用户原始数据
    ↓ 实体消歧、时间截断、证据归并
关系证据图
    ↓ 建图策略
确定边 + 不确定边 + 超边/事件节点
    ↓ 置信度采样或加权传播
RiskGNN
    ↓
风险均值 + 图不确定性区间 + 敏感性
```

## 1. 企业数据如何建图

首先不能因为字段相似就默认两家企业存在关系。建图必须来自明确的业务语义。

建议将图分成三层：

| 层次     | 内容                         | 示例                                   |
| -------- | ---------------------------- | -------------------------------------- |
| 实体层   | 可识别的真实对象             | 企业、自然人、地址、账户、司法案件     |
| 证据层   | 支持关系存在的原始记录       | 股东登记、担保合同、交易记录、地址登记 |
| 模型图层 | 经过时间截断和规则转换后的图 | 控股边、担保边、共同地址超边           |

### 普通边

适合表达二元关系：

- 企业 A 持有企业 B；
- 企业 A 为企业 B 提供担保；
- 人员 P 担任企业 A 的董事；
- 企业 A 向企业 B 付款；
- 企业 A 涉及案件 C。

每种关系都要明确：

- 是否有方向；
- 是否允许多重关系；
- 是否有起止时间；
- 强度如何定义；
- 来源是什么；
- 是否属于推断关系。

当前代码会为每条关系生成独立的反向关系类型，例如 `ownership` 和 `reverse:ownership`，见 [gnn.py (line 169)](../../com_risk_model/workbench/gnn.py:169)。这比简单无向化更合理，但还缺少时间和证据来源。

### 超图

超图有设计空间，但不应该把所有分组字段都做成超边。

适合使用超边的场景是“一次关系天然涉及多个主体”：

- 多家公司共同参与一个银团贷款；
- 多个企业属于同一个实际控制人集团；
- 多方参与同一担保链或诉讼案件；
- 多家企业共享一个具有风险意义的注册地址；
- 同一供应链订单涉及采购方、供应商、担保方和物流方。

例如：

```
担保合同 H001
├── 企业 A：借款人
├── 企业 B：担保人
├── 企业 C：反担保人
└── 银行 D：债权人
```

但这里还有一个选择：

- 如果只关心“这些节点属于同一个集合”，可以使用超边；
- 如果各主体具有不同角色、方向和属性，更推荐把合同或案件建成一个事件节点，形成异构二部图。

```
企业 A ──借款人──→ 担保合同 H001
企业 B ──担保人──→ 担保合同 H001
银行 D ──债权人──→ 担保合同 H001
```

事件节点通常比纯超边更容易解释，也能保存金额、日期、状态等信息。

### 不应默认做成超图的字段

行业、地区、企业类型、资质等字段通常已经包含在节点特征中。如果再把“同行业企业”全部放进一个超边，相当于重复注入相同信息，还可能制造巨大且稠密的风险传播通道。

现有 SMEsD 结果也没有证明超图有效：`full` 的平均 AUC 为 `0.7891`，反而略低于 `no_hyper` 的 `0.7916`。因此超图必须对应真实的群体作用机制，而不能只是“拥有相同类别”。

### 用户没有关系数据时

应该允许三种结果：

1. 有真实关系数据：训练 RiskGNN。
2. 只有企业属性：使用表格基线或 RiskGNN 的自身风险分支。
3. 只有相似字段：可以构造“候选相似图”，但必须标记为推断图，并单独进行敏感性实验。

不建议系统根据行业、地址文本或财务相似度静默生成“真实关系”。相似并不等于控制、担保、交易或风险传染。

## 2. 如何处理关系不确定性

这个问题目前确实没有被充分表达。

当前 Bundle 的关系只有：

```
graph_snapshot_id
source_id
target_id
relation_type
weight
```

并且只校验 `weight > 0`，见 [data.py (line 137)](../../com_risk_model/workbench/data.py:137)。超边也只有类型、编号和成员，没有置信度，见 [data.py (line 168)](../../com_risk_model/workbench/data.py:168)。

更重要的是，当前 RiskGNN 将 `weight` 放入注意力：

```
alpha = softmax(attention_logit + log(weight))
```

见 [model.py (line 73)](../../com_risk_model/runtime/src/com_risk_runtime/model.py:73)。

这意味着当前 `weight` 表达的是“邻居之间的相对传播强度”，并不是“这条边存在的概率”。两者不能混用。例如一个节点只有一个邻居时，即使其 `weight=0.01`，softmax 后仍然可能得到接近 1 的注意力，它不会真正削弱这条低可信边的影响。

### 应当拆分的关系字段

建议关系至少增加：

```
relation_id
relation_type
source_id
target_id

strength               # 业务强度，如持股比例、担保金额
existence_confidence   # 关系存在的可信度，0~1
source_system          # 工商、司法、人工、第三方推断
evidence_count
observed_at
valid_from
valid_to
is_inferred
```

其中：

- `strength` 回答“关系有多强”；
- `existence_confidence` 回答“我们有多相信它存在”；
- `source_system` 回答“为什么相信它”；
- `is_inferred` 区分事实关系和模型推断关系。

如果置信度没有经过校准，不要轻易把它称为概率。可以先使用 `A/B/C/D` 证据等级，在敏感性实验中映射为不同区间。

超边则需要两种置信度：

- `hyperedge_confidence`：这个群体关系是否真实存在；
- `membership_confidence`：某个节点是否真的属于该群体。

### 模型层面的建议

最实用的方案不是立即上完整贝叶斯 GNN，而是分三步。

第一步：确定图对照

同时训练：

- 表格基线；
- 只使用高可信边的 RiskGNN；
- 使用全部边但忽略置信度的 RiskGNN。

这样首先能判断低可信关系究竟带来提升还是噪声。

第二步：置信度感知传播

关系强度仍参与邻居间的注意力竞争：

\[ \alpha_{ij}=\operatorname{softmax}(a_{ij}+\log s_{ij}) \]

但置信度放在归一化之后：

\[ m_i=\sum_j q_{ij}\alpha_{ij}W h_j \]

其中：

- \(s_{ij}\) 是业务强度；
- \(q_{ij}\) 是关系存在置信度。

这样即使一个节点只有一个低可信邻居，`q=0.1` 也会让传播消息真正缩小，而不是被 softmax 重新放大到 1。

第三步：随机图推理

对于不确定边：

\[ z_{ij}\sim\operatorname{Bernoulli}(q_{ij}) \]

每次推理抽样一张可能的图，重复例如 20–50 次，最终输出：

- 平均风险概率；
- 5%–95% 风险区间；
- 不同图采样下的标准差；
- 对关系不确定性的敏感程度。

这样系统不再只输出“风险为 0.73”，而可以输出：

```
平均风险：0.73
图不确定性区间：0.61–0.81
主要不确定来源：两条推断控制关系、一条低可信共同地址关系
```

这比把不确定关系当成确定事实更适合人工风控复核。

## 对当前项目的具体建议

下一版不需要重新变成多个产品算法，可以仍然只有一个 RiskGNN，但增加三个实验配置：

| 配置                      | 作用                           |
| ------------------------- | ------------------------------ |
| `self_only`               | 不使用图，判断企业自身信息上限 |
| `high_confidence_graph`   | 只使用高可信事实关系           |
| `uncertainty_aware_graph` | 使用全部关系并显式建模置信度   |

同时保留 HGB 作为表格基线。这样比较的是同一个 RiskGNN 的信息与鲁棒性消融，不会再次造成“多个算法合并还是拆分”的概念混乱。

我建议优先顺序是：

1. 先扩展 Bundle 契约，分离 `strength` 和 `confidence`。
2. 为关系和超边增加来源、时间及推断标记。
3. 建立“无图／高可信图／全图”三组对照。
4. 再实现置信度感知传播。
5. 最后加入随机图推理和预测区间。

最重要的设计原则是：图不仅要记录“谁和谁相连”，还必须记录“为什么相连、何时相连、我们有多相信这条关系”。否则 GNN 的传播能力越强，错误关系造成的风险扩散反而越严重。
