# UK 财务决策模型：uk-financial-0.6b-v1

## 身份与用途

- 底座：Qwen/Qwen3-0.6B，固定 revision `c1899de289a04d12100db370d81485cdf75e47ca`。
- 模型：协作者提供的财务版 LoRA，加载时必须恢复 `decision_runtime.json`。
- 任务：匹配研究队列中，未来 12 个月首次观察到主要正式破产程序的二分类。
- JevForge 固定提交：`8986e521b8220dc41ff4de44fb418dc0da02afea`。
- 候选顺序固定为 `no_event`、`event`，使用 tree 模式候选评分，不生成自由文本。

适用于本地模型加载、集成与数值核验。匹配队列中的分类分数不等于总体企业违约概率，
也不能直接作为授信决策。本版财务模型不消费图结构，不能以关系图解释其预测贡献。

## 输入与输出

`input-contract.json` 固定了允许特征、问题文本、候选顺序、序列化方式与 2048 token 上限。
仅将 `state.features` 输入模型；expected、企业标识和审计字段不进入提示。
未知特征、null、非有限数值、改变的问题和超长输入报错；不自动填零、不截断。
未列出的特征表示缺失；实际零值、负值及币种保留。数值单位由数据提供方确认。

输出 `rawProbabilities` 为候选评分归一化结果，按上述标签顺序解释。
完整 v1 同时输出 `rawProbabilities` 和 `calibratedProbabilities`，原始分数始终保留。
正式校准温度为 0.8826538438450512；仅适用于匹配研究样本，不是总体破产概率。
adapter 内 tokenizer 与模板保留作来源记录，实际使用固定底座的 tokenizer。
原始 adapter_config 中的训练机绝对路径仅作记录；加载时显式指定本地底座。

## 校准来源

原始 `calibration.json` 包含 4,046 个样本 ID、标签、原始分数及温度，随模型包分发。
其大小和 SHA-256 固定在版本定义 `calibration_file`，推理只读取温度。
样本及顺序与本地完整数据的训练期独立校准划分一致，正负各 2,023 条。
重新拟合温度与提供值一致，研究代码与服务代码的校准结果在浮点误差内一致。

## 验证状态与缺项

2026-10-18，本地 CPU/float32、RTX4060 Laptop/CUDA/bfloat16 及禁网 CPU 容器
均完成缺失财务输入探针。参考输入与分设备结果位于 `acceptance/`，仅验证加载和数值变化。
它们不是真实企业验收集，不证明模型质量或训练服务器结果复现。
CPU 与 GPU 使用不同精度，参考结果和容差分别记录，不要求逐位相同。
